# スクワットを数えよう（ブラウザの中のリザバーコンピューティング）

スマホの動き（DeviceMotion の加速度）から、スクワットの回数を数える。3 回分の動きを見せるだけで、出力の重みをその場で学習する。外の読み込み無しの 1 枚の HTML と、AI エージェントが使う MCP の口を持つ。

## 構成

| ファイル | 役割 |
|---|---|
| `app/esn.js` | 計算の部品（リザバー・リッジ回帰・山の検出・数える・作り物の波）。画面・MCP・試験が同じ物を使う |
| `app/index.src.html` | 画面の元。`/*__ESN__*/` の所へ esn.js をそのまま埋め込む |
| `app/index.html` | 出来上がりの 1 枚（`node build.mjs` で作る・外へ出る処理なし） |
| `app/llms.txt` | AI 向けの短い説明 |
| `mcp/server.mjs`・`mcp/README.md` | MCP の stdio サーバーと説明 |
| `test/test.mjs`・`test/mcp_session.mjs` | 計算の試験・MCP を実際に起こす確かめ |
| `shots/` | 撮った画面（390x844 と 1440x900）と撮影用の頁 `cap.html` |

## 使い方

- 画面: `app/index.html` を開く。「まず 3 回」→スクワット 3 回→「覚える」→「数え始める」。iPhone は https のページで開き、押した時に出る動きの許可を通す。パソコンなどセンサーの無い端末では「見本の動き（作り物）」で試せる（作り物の波形と画面に書いてある）。
- 組み直し: `node build.mjs`
- 試験: `node test/test.mjs`
- MCP の確かめ: `node test/mcp_session.mjs`

## 計算の中身

- 入力 4（加速度の大きさから重力の平均を引いた 1 本＋3 軸それぞれ）。50Hz 前後に間引く。
- リザバー: 内部 100・結合は 10% の疎・スペクトル半径 0.9・漏れ率 0.3・乱数の種は固定（同じ種なら必ず同じ物ができる）。
- 学習: 出力の重み 105 個（内部 100＋定数＋入力 4）だけをリッジ回帰で解く。行列は自前のコレスキー分解で解く（数十行）。
- 目標の波: 1 回ごとの印で 1・印と印の中間で 0 になる波。印は、利用者がたたいた時刻（近い山があればそこへ寄せる）か、3 回分の波の山から自動。動きの外は 0。
- 学習データの足し方（過学習を防ぐため）: 元の 3 回分に雑音を足した写し 4 つと、動かない時の見本（その波の雑音の大きさから作った雑音だけの 12 秒・目標 0）を足す。
- 数える: 出力が 0.55 を上へ横切ると 1 回・0.3 を下へ戻るまで次を数えない・1 秒より短い間隔は数えない。

## 確かめた範囲

- `node test/test.mjs`: 作り物の波（種を固定・雑音あり）で 3 回分を学習し、10 回と 20 回（1 回 1.6〜2.6 秒）を数えた回数が正解の ±1 以内か。動かない信号は 0 回か。
- 実機のセンサーでは未検証。作り物の波は 1 回の動きを「cos＋第 2 高調波」で作った単純な形で、実際のスクワットとは違う。
- 作り物の波での限界（調整中に測った値）: 学習の 3 回が 1.6 秒で数える相手が 2.4 秒まで遅いと数え落としが出る・学習の 3 回が 3.0 秒と遅く動きが小さいと、動かない信号で誤って数える。
- 「少ない計算量と少ない学習で時系列を扱える」は、この作品の範囲で数える仕事ができたという意味で、他の仕事での優位は確かめていない。
